# SKILLS.md

Описание отдельных "скиллов" (модулей) LLM/обработки в проекте dagestan-trip-bot.
Каждый скилл — независимый шаг пайплайна с чётким входом/выходом. При добавлении
нового скилла — копировать формат ниже и дополнять этот файл.

---

## 1. video-ingest

**Когда используется:** пользователь прислал в Telegram видео-файл, ссылку на
Instagram-пост или скриншот.

**Вход:** объект сообщения Telegram (файл / текст со ссылкой / фото).

**Выход:** нормализованная запись `RawItem`:
```
{ id, type: "video"|"link"|"screenshot", file_path|url, caption_text, received_at }
```

**Логика:**
- Если пришёл видео-файл — сохранить локально, дальше в `frame-extraction`.
- Если пришла голая ссылка на пост — попытаться получить caption через официальный
  oEmbed (если доступен); если не получилось — попросить пользователя переслать
  сам файл, а не ссылку.
- Если пришёл скриншот (например, комментария) — сразу в `vision-analysis`, минуя
  extract/transcribe.

**Не делает:** не пытается логиниться в Instagram, не скрейпит приватные эндпоинты.

---

## 2. frame-extraction

**Когда используется:** после `video-ingest`, если тип входа — видео.

**Вход:** путь к видеофайлу.

**Выход:** список путей к кадрам (JPEG, ~1 кадр/сек, но не больше `MAX_FRAMES`
константы — чтобы не раздувать счёт за vision-вызовы) + путь к аудиодорожке (WAV).

**Инструмент:** `ffmpeg` (системный вызов, обёрнутый в отдельную функцию
`extract_frames_and_audio(path) -> (frames: list[str], audio: str)`).

**Важно:** временные файлы удаляются после того, как `vision-analysis` и
`transcription` их обработали — не хранить на диске дольше одного цикла обработки.

---

## 3. transcription

**Когда используется:** есть аудиодорожка из `frame-extraction`.

**Вход:** путь к WAV-файлу.

**Выход:** `{ transcript: str, language: str, confidence: float }`.

**Инструмент:** локальный `faster-whisper` (модель `small` или `medium` —
компромисс между качеством и скоростью на CPU). Облачный API — только как fallback,
если локальная модель недоступна.

**Важно:** если аудио пустое/без речи (только музыка) — вернуть `transcript: ""`,
не считать это ошибкой пайплайна.

---

## 4. vision-analysis

**Когда используется:** есть кадры из `frame-extraction` или отдельный скриншот
из `video-ingest`.

**Вход:** список путей к изображениям.

**Выход:** `{ overlay_text: str, recognized_place: str|null, vision_confidence: float }`.

**Модель:** GLM-4.6V (vision) через ключ GLM Coding Plan (см. AGENTS.md,
раздел "какой API-ключ использовать").

**Промпт (базовый шаблон):**
```
Посмотри на эти кадры из видео о путешествии по Дагестану.
1. Есть ли на кадрах текстовые наклейки/подписи с названием места? Если да —
   выпиши точный текст.
2. Узнаёшь ли ты конкретную достопримечательность (каньон, крепость, водопад,
   аул, кафе и т.д.)? Если да — назови её.
Если ничего не удаётся определить — так и скажи, не выдумывай.
```

**Важно:** ограничить число кадров, отправляемых за один вызов (батчить, не по
одному кадру = один API-запрос), чтобы не плодить лишние вызовы.

## 5. text-aggregation

**Когда используется:** после того как для одного `RawItem` собраны caption,
transcript и vision-данные (какие-то из них могут отсутствовать).

**Вход:** `{ caption, transcript, overlay_text, recognized_place }`.

**Выход:** структурированный JSON локации:
```json
{
  "name": "строка или null",
  "region": "строка или null",
  "place_type": "природа|еда|жильё|достопримечательность|другое",
  "raw_sources": ["caption", "transcript", "vision"],
  "confidence": 0.0
}
```

**Модель:** GLM (текстовая), температура низкая (0.1-0.3), просить строго JSON
без пояснений.

**Правило уверенности:** если `confidence < CONFIDENCE_THRESHOLD` — не сохранять
молча, а передать в `user-clarification`.

---

## 6. user-clarification

**Когда используется:** `text-aggregation` вернул низкую уверенность, или поля
`name`/`region` оба `null`.

**Вход:** черновая запись локации + исходный `RawItem`.

**Выход:** либо уточнённые данные от пользователя (текстовый ответ в чате),
либо пометка `skipped`, если пользователь не ответил / не знает.

**Логика:** бот отправляет короткое уточняющее сообщение в чат, например:
"Не понял, что это за место — можешь подсказать название?" Ответ пользователя
идёт обратно в `text-aggregation` как дополнительный источник.

---

## 7. geocoding

**Когда используется:** локация сохраняется, но координат ещё нет.

**Вход:** `name + region` из структурированной записи.

**Выход:** `{ lat, lng, formatted_address }` или `null`, если не найдено.

**Важно:** если геокодинг не нашёл точку — не блокировать сохранение записи,
помечать `needs_manual_location: true` для ручной проверки позже.

---

## 8. storage

**Когда используется:** финальный шаг для каждой обработанной локации.

**Вход:** полная структура локации (name, region, type, coords, confidence,
raw_sources, timestamps).

**Выход:** запись в таблице `locations` (SQLite/Postgres).

**Схема таблицы (минимум):**
```
id, name, region, place_type, lat, lng, confidence,
needs_manual_location, source_message_id, created_at
```

---

## 9. route-planner

**Когда используется:** пользователь запрашивает построение маршрута
("построй маршрут на 10 дней", "собери что у нас есть в Дербенте" и т.д.).

**Вход:** параметры поездки (число дней, бюджет, стиль — насыщенный/спокойный,
способ передвижения, точки старта/финиша) + все локации из `storage` с
`needs_manual_location = false`.

**Выход:** маршрут по дням: список локаций на день с учётом географической
близости, разумного количества точек в день и указанного стиля (баланс
насыщенных/отдыхающих дней).

**Важно:** это отдельный от ingest-пайплайна флоу, вызывается по явной команде,
не автоматически после каждого нового сохранённого места.

## Общие правила для всех скиллов

- Каждый скилл — чистая функция (вход → выход), без побочных обращений к другим
  скиллам напрямую. Оркестрация — в отдельном модуле `pipeline/orchestrator.py`.
- Любой скилл, вызывающий внешний API, должен логировать: какой скилл, сколько
  токенов/вызовов потрачено — это нужно для контроля расходов и квот (см.
  `AGENTS.md`, раздел "какой API-ключ использовать").
- Ни один скилл не должен пытаться получить доступ к приватным данным Instagram
  (сохранённое, лайкнутое, комментарии через неофициальные эндпоинты).
