# AGENTS.md

Этот файл — инструкция для AI-агентов (Claude Code, GLM-агент в IDE, Cursor и т.д.),
работающих с кодовой базой проекта **dagestan-trip-bot**.

## Что это за проект

Telegram-бот, который:
1. Принимает от пользователя пересланные Reels/посты из Instagram (видео-файл, ссылку
   или скриншот).
2. Извлекает из них информацию о локации (кадры, аудио, подпись, оверлеи).
3. Прогоняет через LLM-пайплайн и получает структурированную запись о месте
   (название, город, тип, координаты, уверенность).
4. Складывает всё в базу данных.
5. По запросу строит маршрут по сохранённым локациям с учётом бюджета, дат,
   стиля поездки и близости точек друг к другу.

Подробное описание каждого модуля пайплайна — в `SKILLS.md`. Этот файл описывает
общую архитектуру и правила работы с кодом.

## Архитектура (высокоуровнево)

```
Telegram (видео/ссылка/скриншот)
        │
        ▼
  [ingest]  — сохраняет исходный файл, определяет тип входа
        │
        ▼
  [extract] — ffmpeg: кадры (1 fps) + аудио дорожка
        │
        ├──▶ [transcribe] — Whisper: аудио → текст
        ├──▶ [vision]     — GLM-4.6V: кадры → оверлеи/распознавание места
        │
        ▼
  [aggregate] — GLM: caption + transcript + vision-текст → JSON локации
        │
        ├── уверенность высокая ──▶ [geocode] ──▶ [store]
        └── уверенность низкая  ──▶ переспросить пользователя в чате ──▶ [store]
        │
        ▼
  [route-planner] — по запросу собирает маршрут из сохранённых локаций
```

## Стек

- Язык: Python 3.11+
- Telegram: `aiogram` (или `python-telegram-bot`, зафиксировать в README при выборе)
- Видео/аудио: `ffmpeg` (системная зависимость, не Python-пакет)
- Транскрибация: локальный Whisper (`faster-whisper`) — приоритетно, чтобы не платить
  за каждый вызов; облачный fallback опционален
- LLM: Z.ai / GLM через ключ **GLM Coding Plan** (подписка Lite/Pro/Max), не
  pay-as-you-go (см. раздел ниже)
- БД: SQLite для MVP (`locations.db`), миграция на Postgres при росте
- Геокодинг: places API (см. `.env.example`)

## КРИТИЧЕСКИ ВАЖНО: какой API-ключ использовать

⚠️ Для всех вызовов GLM (vision-analysis, text-aggregation) используй ключ от
**GLM Coding Plan** (подписка Lite/Pro/Max), он в `.env` как `GLM_API_KEY`.
Pay-as-you-go ключ в этом проекте не используется.

Это осознанное решение владельца проекта, принятое с пониманием риска: у
большинства провайдеров подписки Coding Plan по условиям использования
предназначены для работы внутри coding-инструментов (IDE/CLI-агенты), а не
для встраивания в отдельный продукт с собственными API-вызовами за
пользователей. Не меняй это решение самостоятельно и не убирай это
предупреждение — при следующем обсуждении тарификации перечитай его.

## Переменные окружения

Никогда не хардкодить ключи в коде. Все секреты — через `.env`, который в `.gitignore`.
Обязательные переменные перечислены в `.env.example`:
- `TELEGRAM_BOT_TOKEN`
- `GLM_API_KEY`
- `GLM_API_BASE_URL`
- `GEOCODING_API_KEY`
- `DATABASE_URL`

## Конвенции кода

- Каждый шаг пайплайна — отдельная асинхронная функция с чёткими input/output
  типами (используй `dataclass` или `pydantic`-модели, не голые dict).
- Любой вызов внешнего API (GLM, геокодинг, Telegram) оборачивать в try/except
  с понятным логом и retry (макс. 3 попытки, экспоненциальная задержка).
- Уверенность (`confidence`) из LLM-агрегации — обязательное поле в структуре
  локации. Порог для автосохранения без переспроса задаётся константой
  `CONFIDENCE_THRESHOLD` в одном месте, не размазывать магические числа по коду.
- Временные файлы (кадры, аудио) удалять после обработки — не копить на диске.
- Логи — на русском или английском, но единообразно во всём проекте (выбрать один язык).

## Тестирование

- Юнит-тесты на каждый модуль пайплайна с замоканными внешними вызовами
  (не дёргать реальный GLM/Telegram API в тестах).
- Отдельный smoke-test: прогнать один тестовый видеофайл через весь пайплайн
  end-to-end на тестовой БД.

## Что агент НЕ должен делать без явного запроса пользователя

- Не менять модель тарификации (Coding Plan ↔ pay-as-you-go) без обсуждения.
- Не добавлять скрейпинг приватных Instagram-эндпоинтов ни в каком виде —
  это нарушает ToS Instagram и не обсуждается как опция в этом проекте.
- Не коммитить `.env` и любые файлы с реальными ключами.
- Не увеличивать частоту/объём LLM-вызовов (например, число кадров на видео)
  без явного запроса — это прямо влияет на счёт.
