# dagestan-trip-bot

Telegram-бот для сбора локаций для путешествия по Дагестану из видео/ссылок,
которые пересылаются в чат, и последующего построения маршрута поездки.

Архитектура и конвенции проекта — в [AGENTS.md](AGENTS.md), описание
пайплайн-модулей ("скиллов") — в [SKILLS.md](SKILLS.md).

## Статус

**Итерация 1:**
- скелет Telegram-бота (aiogram): принимает пересланное видео, сохраняет его
  локально в `media/videos/`, отвечает подтверждением. Реальной обработки
  (распознавание места и т.д.) ещё нет — это заглушка;
- модуль `pipeline/frame_extraction.py` — ffmpeg-обёртка, извлекающая кадры
  (1 кадр/сек, не больше `MAX_FRAMES`) и аудиодорожку из видео, с юнит-тестами.

**Итерация 2:**
- модуль `pipeline/transcribe.py` — локальная транскрибация аудио через
  `faster-whisper` (модель `small` по умолчанию), с юнит-тестами (модель
  замокана, реальных загрузок в тестах нет). Если в аудио нет речи — модуль
  возвращает пустой транскрипт, это не ошибка.

**Итерация 3:**
- модуль `pipeline/vision.py` — анализ кадров через GLM-4.6V (прямой вызов
  OpenAI-совместимого эндпоинта `/chat/completions`, ключ GLM Coding Plan).
  Кадры батчатся (до `VISION_MAX_IMAGES_PER_BATCH` за один вызов), есть retry
  с экспоненциальной задержкой и разбор JSON-ответа (в т.ч. в
  markdown-обёртке). 16 юнит-тестов с замоканным HTTP + проверено вживую на
  реальном ключе.

**Итерация 4:**
- модуль `pipeline/aggregate.py` — агрегация caption/transcript/vision-данных
  в структуру локации через текстовую модель `glm-5` (тот же ключ Coding
  Plan). Порог `CONFIDENCE_THRESHOLD` задан в одном месте (используется
  будущим `user-clarification`/оркестратором). 7 юнит-тестов с замоканным
  HTTP + проверено вживую на реальном ключе.

**Итерация 5:**
- модуль `storage/db.py` — SQLite-хранилище локаций (таблица `locations` по
  схеме из SKILLS.md). `path_from_database_url()` разбирает `DATABASE_URL`
  вида `sqlite:///...`. `list_locations(only_geocoded=True)` — фильтр,
  которым позже воспользуется route-planner. 7 юнит-тестов на реальном
  временном файле SQLite (это не внешний API, мокать нечего).

**Итерация 6:**
- модуль `pipeline/geocode.py` — поиск координат по названию места через
  **Nominatim (OpenStreetMap)**, бесплатно, без API-ключа (выбран специально,
  чтобы весь пайплайн, кроме GLM Coding Plan, оставался бесплатным).
  `GEOCODING_API_KEY` в `.env.example` зарезервирован под платный провайдер
  на будущее, сейчас не используется. Если место не найдено —
  `geocode_location()` возвращает `None`, это штатный случай (вызывающий код
  в будущем оркестраторе проставит `needs_manual_location=true`, не блокируя
  сохранение). 6 юнит-тестов с замоканным HTTP + проверено вживую.

**Итерация 7:**
- `pipeline/orchestrator.py` — связывает все скиллы в одну цепочку:
  `extract → (transcribe, vision) → aggregate → geocode/needs_manual_location
  → store`. Вычисляет `needs_clarification` (низкая уверенность или name и
  region оба пустые), но сам диалог с пользователем (SKILLS.md, скилл 6,
  user-clarification) — будущая работа в слое `bot`, здесь только флаг.
  Временные файлы (кадры/аудио) удаляются после обработки. 6 юнит-тестов
  (все скиллы замоканы) + полный live smoke-test на реальном
  видео/GLM/Nominatim/SQLite.
- **Найдено и исправлено вживую:** `glm-5`/`glm-4.6v` — reasoning-модели
  (в ответе есть скрытые `reasoning_content` токены помимо видимого
  `content`, оба считаются в `max_tokens`). При тесном лимите `content`
  иногда обрезался до пустой строки — редкий, но реальный перемежающийся
  сбой (тот же запрос повторно отрабатывал штатно). Исправлено: retry
  теперь покрывает и ошибку разбора ответа, не только сетевые сбои;
  `max_tokens` увеличен с 512/1024 до 2048 в обоих модулях.
- Пока не подключено к боту — `bot/handlers.py` всё ещё просто сохраняет
  видео и логирует, реальная обработка не запускается автоматически.

User-clarification (сам диалог в чате) и route-planner — в следующих
итерациях.

### Про faster-whisper

При первом реальном вызове `transcribe_audio()` модель (`small`, ~500МБ)
скачивается с Hugging Face Hub — нужен интернет один раз, дальше модель
кешируется локально (`~/.cache/huggingface`). Скорость на CPU зависит от
длины аудио и мощности машины.

## Установка

### 1. Python-окружение

Требуется Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. ffmpeg

Системная зависимость, не Python-пакет. На macOS:

```bash
brew install ffmpeg
```

Проверить, что всё встало:

```bash
ffmpeg -version
```

### 3. Переменные окружения

Скопируйте шаблон и заполните реальными значениями:

```bash
cp .env.example .env
```

Обязательные переменные (см. `.env.example` для комментариев):

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) — нужен уже в этой итерации |
| `GLM_API_KEY` | ключ Z.ai/GLM — используется в следующих итерациях (vision, aggregation) |
| `GLM_API_BASE_URL` | базовый URL GLM API — используется в следующих итерациях |
| `GEOCODING_API_KEY` | ключ геокодинг-сервиса — используется в следующих итерациях |
| `DATABASE_URL` | путь к SQLite-файлу, например `sqlite:///storage/locations.db` |
| `MEDIA_STORAGE_DIR` | локальная папка для сохранённых видео (по умолчанию `media/videos`) |

**Важно:** для `GLM_API_KEY` в этом проекте по решению владельца используется
ключ от **GLM Coding Plan**, а не pay-as-you-go ключ. Учтите: обычно такие
ключи по условиям использования предназначены для работы внутри
coding-инструментов, а не для встраивания в отдельный продукт — подробности
см. в `.env.example`. В этой итерации реальных вызовов GLM ещё нет.

`.env` в `.gitignore` — никогда не коммитьте реальные ключи.

## Запуск бота

```bash
source .venv/bin/activate
python -m bot.main
```

Бот запустится в режиме long polling. Перешлите ему видео из Instagram —
он сохранит файл в `media/videos/` и ответит подтверждением. Остальные типы
сообщений (текст/ссылки, фото/скриншоты) пока получают заглушку-ответ.

## Тесты

```bash
source .venv/bin/activate
pytest
```

Тест `tests/test_frame_extraction.py` генерирует короткое тестовое видео
на лету через `ffmpeg` (без бинарных файлов в репозитории) и проверяет
извлечение кадров и аудио, соблюдение `MAX_FRAMES`, поведение для видео без
звука и обработку отсутствующего файла.

## Структура проекта

```
/bot            — обработчики Telegram, роутинг сообщений
/pipeline       — модули ingest/extract/transcribe/vision/aggregate/geocode
/routeplanner   — логика построения маршрута
/storage        — доступ к БД, модели данных
/tests
.env.example    — список переменных окружения (без значений!)
```
